# PII / identity / session ROOTS for sandbox snapshot exclusion.
#
# These are the identity and session tables whose ROWS must never be cloned
# into a sandbox.  Their FK-dependent descendants are computed automatically
# at snapshot time via a recursive CTE over pg_constraint, so only the roots
# need to be listed here.  A future user-owned table (e.g. watch ownership
# adding user_id) will be auto-excluded with no hand-editing required.
#
# The watch subtree (availability_watch, availability_watch_target,
# availability_watch_poller, availability_job, availability_job_run,
# availability_fetch_call) is NOT listed here.  Instead, the single PII
# column in that subtree — availability_watch.trigger_config (JSONB holding
# email recipients and Slack channels) — is scrubbed in place after restore
# by scripts/sandbox_scrub.sql.  This preserves all watch rows and FK
# integrity while removing notification destinations.
#
# Two guard heuristics in SandboxPrivateTablesTest.kt derive the PII set:
#   1. FK heuristic: tables with a column REFERENCES app_user (ownership).
#   2. Column heuristic: tables whose CREATE TABLE or ALTER TABLE ADD COLUMN
#      block contains a column matching sensitiveColumnPatterns.
# Every derived table must be COVERED by either appearing in this roots list
# or being the scrub target (availability_watch via sandbox_scrub.sql).
#
# After restore, scripts/sandbox_seed_users.sql re-seeds app_user and
# user_role with two fixed sandbox-only users (will/matt @sandbox.local).

# ── Identity / session ────────────────────────────────────────────────────────
app_user
user_identity
user_session
user_role
user_settings

# ── Legacy key/value store ────────────────────────────────────────────────────
# Unclassified generic key/value table from V2 migrations; included
# defensively since its schema predates PII classification.
settings
